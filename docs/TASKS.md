# Бэклог

План сверен с ТЗ хакатона «Кибер 102» (АО «Салаватстекло»). Задачи разбиты на два потока,
файлы у потоков почти не пересекаются.

- **Поток A — «AI и контент»** — напарник ([@wxqryy](https://github.com/wxqryy)).
- **Поток B — «платформа, компании, доставка»** — Урал ([@Yralskui](https://github.com/Yralskui)).

Приоритеты: **P0** — без этого не пройти приёмку, **P1** — желательно для демо,
**P2** — для конечного продукта, на хакатоне только упоминаем в «доработках».

## Демо (вместе, в конце)

1. Администратор создаёт компанию и загружает материалы.
2. Клиент ставит задачу → пост с текстом и картинкой → согласование → «Изменить» → одобрение →
   пост в канале → AI сообщает результат → уточняющий вопрос с опорой на историю.
3. Отклонённый пост не публикуется.
4. Автономный черновик по расписанию.
5. Вторая компания: свои данные, чужих не видно.
6. Перезапуск контейнера — работа продолжается.
7. ChatGPT: вход, возможности, ограничения.

## Что режем, если не успеваем

Не трогаем: контент-план, VK, MAX, аналитику, конкурентов, видео, комментарии — всё это в
D4 «доработки». Последними отбрасываем: провайдер ChatGPT (остаётся документ A3), B5, A5.

## Как не сломать код при слиянии

- Файлы потоков разные (списки выше). В общих `bot/texts.py` и `bot/keyboards.py` каждый пишет
  только в своей секции в конце файла (`# --- поток A ---` / `# --- поток B ---`).
- `bot/setup.py`: новый роутер — одна строка, ставить перед `chat`.
- `db/models.py` меняет только B1. Этот PR вливается **первым**, напарник сразу делает
  `git pull --rebase origin main`.
- `container.py`: A2 и A3 подключаются через `images/factory.py` и `llm/factory.py`, в контейнер
  заходить не нужно.
- `git pull --rebase origin main` каждые 2–3 часа, PR по одной задаче.

## Как брать задачу

1. Отметить задачу в разделе «В работе» ниже (с именем) или сообщить напарнику.
2. Создать ветку `feature/<коротко>` и работать небольшими PR.
3. Готово = код + тест (где возможно) + `ruff` + `pytest` + `--check` зелёные, задача
   отмечена ✅ в этом файле.
