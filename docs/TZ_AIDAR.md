# ТЗ для Айдара: поток A «AI и контент»

## 0. Контекст

«Автономный AI-маркетолог» — Telegram-бот для хакатона «Кибер 102».
Платформа уже умеет работать с компаниями, согласовывать и публиковать посты в Telegram,
обрабатывать комментарии, вести фотобанк, считать расходы и присылать отчёты. Для сквозных
тестов используются mock-провайдеры. Для текста и изображений есть OpenAI-адаптеры. Нужно проверить их с живым ключом.

Перед работой прочитай `CLAUDE.md`, `docs/ARCHITECTURE.md`, `docs/TASKS.md` и
`docs/AI_OPTIONS.md`. Основные точки входа: `app/agent/core.py`,
`app/llm/openai_provider.py`, `app/llm/mock_provider.py`, `app/images/factory.py`.

## 1. Подготовка

Сделано всё, кроме «мозгов»: компании, согласование постов, публикация в канал, расходы,
комментарии, отчёты, фотобанк, бренд-гид, деплой на сервер. Бот уже работает на сервере, но в
**mock-режиме**: тексты и картинки — шаблонные заглушки. **Твоя задача — включить настоящую
нейросеть (ChatGPT API) и довести AI-функции до качества демо.**

Обязательно прочитай в репозитории:
1. `CLAUDE.md` — правила проекта: где что лежит, что нельзя менять, стиль кода.
2. `docs/AI_OPTIONS.md` — сравнение нейросетей, цены, что можно и нельзя с ChatGPT.
3. `docs/ARCHITECTURE.md` — как устроены агент и провайдеры.
4. `app/llm/base.py`, `app/llm/openai_provider.py`, `app/llm/mock_provider.py` — интерфейс
   LLM и примеры провайдеров.
5. `app/agent/core.py` — цикл агента (как он вызывает модель и инструменты).
6. `app/images/base.py`, `app/images/mock_provider.py` — интерфейс генератора картинок.

**Решение команды: ChatGPT API (OpenAI) через прокси.** С сервера в РФ OpenAI напрямую
отвечает 403, через прокси вне РФ работает (проверено: 401 «нужен ключ» за 0,35 с).
Провайдер OpenAI в коде **уже есть** (`app/llm/openai_provider.py`) и уже умеет:
- `LLM_PROXY` — один или несколько прокси через запятую, при сбое переключается на следующий;
- повторы «до конца» в пределах `LLM_RETRY_BUDGET_SECONDS` (по умолчанию 180 с) при обрывах,
  таймаутах, 429 и 5xx; неверный ключ и 403 не повторяются, а дают понятную ошибку;
- точный учёт токенов для `/costs` (из `usage` ответа).
Модель по умолчанию — `gpt-5-mini` (около 45 ₽ в месяц на компанию). Запасной вариант, если с
оплатой OpenAI не выйдет, — GigaChat (см. `docs/AI_OPTIONS.md`).

**Бренд-гид («скилл» стиля компании) уже есть:** `app/services/brand.py`. Он автоматически
добавляется к профилю бизнеса, а значит, во все промпты. Для Салаватстекла есть готовый шаблон
по их брендбуку (`app/services/brand_presets.py`). Не дублируй его в промптах — просто пиши
промпты так, чтобы модель соблюдала раздел «Бренд-гид» из профиля.

## 1. Подготовка (один раз)

1. Склонируй репозиторий и поставь окружение — раздел «Быстрый старт» в `README.md`.
   Проверь, что всё зелёное:
   ```bash
   ruff check . && ruff format --check . && pytest && python -m app.main --check
   ```
2. **Создай свой тестовый бот** через @BotFather и впиши его токен в свой `.env`.
   ⚠️ Боевой токен `@ai_marketolog1_bot` локально **не запускай**: он уже работает на сервере,
   два процесса с одним токеном мешают друг другу.
3. В свой `.env`: `ALLOWED_USER_IDS=<твой Telegram ID>`, `TELEGRAM_CHANNEL_ID=` — свой тестовый
   канал, куда твой бот добавлен админом. `PUBLISH_DRY_RUN=true`, пока отлаживаешь.
4. Ключ OpenAI (`LLM_API_KEY`) возьми у Урала — **только в `.env`**, в Git не коммитить.
   В `.env`: `LLM_PROVIDER=openai`, `LLM_MODEL=gpt-5-mini`, `LLM_BASE_URL=https://api.openai.com/v1`.
   Если ты в России — нужен прокси вне РФ в `LLM_PROXY` (тот же, что у сервера, тоже у Урала).
   Цены для `/costs` (gpt-5-mini, ₽ за 1 млн токенов при ~100 ₽/$):
   `LLM_PRICE_INPUT_PER_1M=25`, `LLM_PRICE_OUTPUT_PER_1M=200`.
5. Работай в ветках: `git pull --rebase origin main`, потом `git switch -c feature/chatgpt-prompts`.
   Одна задача — одна ветка — один PR. Коммиты по Conventional Commits на английском
   (`feat: ...`), комментарии и тексты — на русском.

## 2. Задачи по порядку

### Задача A1 — ChatGPT API: отладка на живой модели (P0, главная)

**Цель:** с `LLM_PROVIDER=openai` бот пишет живые посты в стиле бренда, а агент сам вызывает
инструменты (создать черновик, показать посты, правка, отчёт).

Провайдер писать **не нужно** — он есть. Нужно:
1. Подключиться (см. «Подготовка», п. 4) и прогнать `python -m app.main --check`.
2. Пройти сценарий живьём:
   1. `/onboarding` с описанием компании → `/done`;
   2. «🎨 Бренд-гид» → «Шаблон: Салаватстекло» (или загрузить свой брендбук);
   3. «напиши пост про стекло MultiComfort для фасадов с картинкой»;
   4. «✏️ Изменить» → «Короче»;
   5. «что ты знаешь о нашем бизнесе?»;
   6. «покажи мои посты»;
   7. «сделай отчёт».
3. Отладь промпты в `app/agent/prompts/*.md`: `system.md`, `write_post.md`, `revise_post.md`,
   `extract_profile.md`, `extract_brand.md`, `reply_comment.md`, `weekly_report.md`.
   Плейсхолдеры `{{var}}` не переименовывай.
   - Посты — без Markdown, в тоне бренда, точные названия продуктов (MultiComfort° и т.п.).
   - Агент не выдумывает цены и факты; если данных нет — задаёт один уточняющий вопрос.
   - Карточка черновика показывает «⚠️ Проверка бренд-гида», если пост нарушает написание. Цель —
     чтобы на живой модели таких пометок почти не было.
4. Проверь на сервере (попроси Урала задеплоить), что через прокси нет таймаутов на обычных
   запросах.

**Готово, если:** сценарий проходит живьём, тексты не стыдно показать жюри, агент выбирает
правильные инструменты. Тесты — без сети (см. `tests/test_openai_resilience.py` как пример
подмены сети через `httpx.MockTransport`).
PR: `feat: tune prompts on live ChatGPT`.

### Задача A2 — картинки через OpenAI (P0)

**Цель:** «пост с картинкой» приносит осмысленную картинку в стиле бренда, без текста на
изображении.

**Файлы:** новый `app/images/openai_provider.py` (класс от `ImageProvider`, `name = "openai"`),
ветка в `app/images/factory.py` (`IMAGE_PROVIDER=openai`), новый промпт
`app/agent/prompts/image.md`, блок генерации в `app/services/posts.py::create_draft`, тесты.

**Как:**
- Модель — `gpt-image-1-mini` (дешевле) или более новая из прайса OpenAI. Размер 1024×1024,
  качество low/medium (для Telegram хватает). Цену картинки пропиши в `IMAGE_PRICE` для `/costs`.
- Тот же прокси и та же устойчивость: создай `AsyncOpenAI` с `httpx.AsyncClient(proxy=...)` по
  `settings.llm_proxies` и оберни вызов в `app/utils/retry.py::retry_with_budget`
  (как в `openai_provider.py`).
- Описание сцены (`image.md`): из темы поста и профиля компании — 1–2 предложения, что нарисовать.
  Стиль бренда уже подмешивается в описание автоматически (`brand.image_style`) — не дублируй.
- Если генерация упала, пост создаётся **без картинки** и с предупреждением в ответе агента.
  Сейчас ошибка картинки роняет весь черновик.
- Если у компании есть свои фото, `create_draft` получает `image_path` — тогда генерация не нужна.
  Это уже работает.

**Готово, если:** с `IMAGE_PROVIDER=openai` пост с картинкой приходит с осмысленным изображением
в стиле бренда; при сбое генерации пост всё равно создаётся.
PR: `feat: OpenAI image generation with brand style`.

### Задача A3 — ChatGPT, критерий 12 ТЗ хакатона (P0)

ТЗ хакатона требует **проверить**, можно ли использовать существующий аккаунт ChatGPT, и честно
показать результат — **не подменяя его незаметно отдельным API-ботом**.

**Минимум (обязательно):** документ `docs/CHATGPT.md`. Основа — раздел про ChatGPT в
`docs/AI_OPTIONS.md`. Что в нём должно быть:
1. Что проверили и чем (свой аккаунт ChatGPT, тариф).
2. Вывод: подписка Plus/Pro ≠ API, официального способа вызывать модели «за счёт подписки» из
   своего кода нет. С сервера в РФ OpenAI API отвечает 403.
3. Что работает:
   - **свой GPT с Actions** (OpenAPI) — ChatGPT вызывает API нашего бота;
   - **Developer mode / MCP** — проверь на своём аккаунте, есть ли запись на твоём тарифе;
   - **Codex CLI** со входом через ChatGPT (`codex exec`) — только как эксперимент, серая зона
     по правилам тарифа.
4. Чего не делаем: автоматизацию браузера chatgpt.com (нарушает правила, ломается).
5. Скриншоты или шаги, как это показать на защите.

**Если останется время:** демо «Свой GPT с Actions» — владелец пишет в ChatGPT «сделай пост
про акцию», черновик приходит в Telegram на согласование. Для этого нужен небольшой HTTP API
бота с токеном доступа и публичный HTTPS-адрес. **Сначала напиши Уралу** — домен и сервер на нём.

PR: `docs: ChatGPT account usage findings`.

### Задача A4 — автономные черновики, критерий 8 (P1)

**Цель:** без сообщений от пользователя бот сам предлагает тему, пишет пост и присылает
черновик на согласование.

**Файлы:** `app/scheduler/jobs.py::generate_daily_drafts`, `app/scheduler/setup.py`,
`app/config.py`, `.env.example`, новый промпт `app/agent/prompts/suggest_topic.md`, тесты.

**Что сделать:**
1. Перепиши `generate_daily_drafts`, сейчас он завязан на заглушку контент-плана. Для каждой
   компании, у которой заполнен профиль и есть ответственный:
   1. Возьми темы последних постов (`PostRepo.list_for_business`), чтобы не повторяться.
   2. Попроси LLM предложить одну тему (промпт `suggest_topic.md`, ответ — короткая строка).
   3. `posts.create_draft(..., with_image=True)`.
   4. `approval.submit_for_approval(session, post, container.notifier, <telegram_id ответственного>)` —
      см. `_owner_chat_id` в том же файле.
2. ⚠️ Работу по каждой компании оборачивай в `async with usage_scope(session, business.id):`
   (`app/services/usage.py`), иначе расходы не запишутся на компанию.
3. Ошибка одной компании не должна останавливать остальные: `try/except` + `log.exception`.
4. Расписание: по образцу отчётов (`REPORT_INTERVAL_MINUTES` в `setup.py`) добавь
   `AUTO_DRAFTS_INTERVAL_MINUTES`: `0` — каждый день в 9:00, `N` — каждые N минут (для демо).
   Включается флагом `ENABLE_AUTO_DRAFTS=true`.

**Готово, если:** с `ENABLE_AUTO_DRAFTS=true` и `AUTO_DRAFTS_INTERVAL_MINUTES=5` через 5 минут
ответственному приходит черновик с кнопками. Тест — с mock-LLM и FakeNotifier
(см. `tests/conftest.py`).
PR: `feat: autonomous daily drafts with AI-suggested topics`.

### Задача A5 — факты из загруженных материалов, критерий 3 (P1)

**Цель:** на «сколько стоит капучино?» или «какие у нас акции?» агент отвечает цифрами из
загруженного PDF или сайта, а не выдумывает.

**Файлы:** `app/agent/tools/profile_tools.py` (новый инструмент), `app/services/business_profile.py`,
`app/agent/prompts/system.md`, тесты.

**Что сделать:**
1. Инструмент `search_materials(query: str)`: берёт `SourceRepo.list_for_business(ctx.business_id)`,
   режет тексты на куски ~800 символов, выбирает 3 самых подходящих по словам запроса (простой
   поиск по ключевым словам без регистра достаточен). Возвращает куски с источником
   (имя файла или URL).
2. Ищет **только в материалах своей компании**: фильтр по `business_id` обязателен.
3. В `system.md`: «если нужны факты о компании (цены, адреса, ассортимент) — сначала вызови
   `search_materials`; если не нашёл — спроси у клиента, не выдумывай».

**Готово, если:** тест — загрузили текст с ценой, запрос находит кусок с этой ценой; материалы
другой компании не находятся.

## 3. Правила (обязательно)

1. **Не менять без согласования с Уралом:** `app/*/base.py` (интерфейсы `LLMProvider`,
   `ImageProvider`, `Publisher`), `app/db/models.py`, машину состояний поста
   (`ALLOWED_TRANSITIONS` в `app/services/posts.py`), `app/services/notifier.py`.
   Если без этого никак — остановись и напиши Уралу.
2. **Публикация — только после согласования:** не давай агенту инструмент публикации и не
   переводи посты в `approved` в обход `services/approval.py`. Это сторожат тесты.
3. Тексты бота — только в `app/bot/texts.py` (новое — в конец файла, в свою секцию
   `# --- поток A ---`), клавиатуры — в `app/bot/keyboards.py`, промпты — в `app/agent/prompts/`.
4. **Секреты** — только в `.env`. Перед пушем проверь, что в diff нет `.env`, ключей и `data/`.
5. Перед каждым PR:
   ```bash
   git pull --rebase origin main
   ruff check . && ruff format --check . && pytest && python -m app.main --check
   ```
6. Тесты — без сети и ключей. Существующие тесты не удалять и не ослаблять.
7. **Деплой на сервер делает Урал** после слияния PR — сам на сервер не заходи.

## 4. Как сдавать

- Одна задача — один PR, в описании: что сделано, как проверить, что затронуто в общих файлах.
- После A1–A3 допиши раздел «Ограничения» в `docs/FEATURES.md` (черновик уже есть).
- Отметь сделанное ✅ в `docs/TASKS.md`.
- Вопросы — в issue #14 на GitHub или Уралу в личку.

**Порядок важности:** A1 → A2 → A3 обязательно к демо; A4 и A5 — сильно усиливают демо; A6 —
по возможности.
