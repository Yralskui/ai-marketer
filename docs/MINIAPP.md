# Telegram Mini App

## Запуск

Для полноценного запуска нужны ключ проекта OpenAI, токен тестового Telegram-бота и
Docker Compose. Используйте существующий `.env` и добавьте настройки из `.env.example`:

- `MINIAPP_PUBLIC_URL` — публичный HTTPS origin для запуска из Telegram. Для проверки HTTP
  на том же Mac подойдёт `http://localhost:8080`. Telegram требует HTTPS для кнопки меню.
- Вход открыт администраторам и пользователям с приглашением. `MINIAPP_OPEN_SIGNUP=true`
  разрешает самостоятельную регистрацию любого аккаунта Telegram.
- `POSTGRES_PASSWORD` — случайный пароль в hex. `S3_ACCESS_KEY` и `S3_SECRET_KEY` —
  случайные учётные данные закрытого локального S3. Compose передаёт их нужным сервисам.
- `LLM_MODEL_LIGHT=gpt-6-luna`, `LLM_MODEL_HEAVY=gpt-6-luna`,
  `EMBEDDING_MODEL=text-embedding-3-small`. Ключ проекта должен иметь доступ к моделям.
- `DEFAULT_PROFILE_FILE` — путь **в контейнере** к JSON профиля, который готовит команда.
  Смонтируйте его read-only. Пример формы: `{"name":"Салаватстекло","description":"…","visual_style":"…"}`.
  Каждый пользователь получает отдельную копию при первом открытии. Без файла это пустой
  профиль «Салаватстекло», который можно выбрать вручную. После подключения файла пустые
  копии заполнятся при следующем открытии. Отредактированные копии сохранят свои настройки.
- `MINIAPP_STORIES_FILE` — необязательный путь в контейнере к JSON-массиву обновлений,
  например `[{"title":"Обновление","text":"…"}]`.

```bash
docker compose -f docker-compose.yml -f docker-compose.miniapp.yml up -d --build
docker compose -f docker-compose.yml -f docker-compose.miniapp.yml ps
```

Проксируйте `/miniapp` и `/miniapp/*` к `127.0.0.1:8080`. На прокси разрешите запрос
размером 100 000 000 байт, настройте ограничение частоты и отключите логирование
Authorization. Бот регистрирует кнопку меню при старте с HTTPS URL. Сервер проверяет
подписанные Telegram `initData` и права профиля на каждом запросе. База и S3 доступны
только во внутренней сети Compose.

Проверка запуска:

1. Выполните `docker compose -f docker-compose.yml -f docker-compose.miniapp.yml ps`
   и убедитесь, что бот и PostgreSQL в состоянии `healthy`, а воркер и S3 запущены.
2. Проверьте готовность командой `curl -fsS http://localhost:8080/readyz`. Страница Mini App
   доступна на `http://localhost:8080/miniapp`. Маршрут `/readyz` нужен только локально.
3. В личном чате с ботом отправьте `/start` и нажмите кнопку открытия приложения. Создайте тестовый профиль,
   добавьте небольшой PDF или PNG и дождитесь статуса «Готово». Попросите в чате
   подготовить пост. Согласуйте его на главной, проверьте расписание и отмените запись.
   Обычный браузер без Telegram может проверить страницу, но не получает подписанные
   данные для доступа к профилям.

Старый Compose остаётся пригоден для локального Telegram-бота с SQLite и файлами на
диске. Стек Mini App заводит отдельную базу PostgreSQL. Перед переключением живого
бота с SQLite требуется перенос данных или согласованный запуск с чистой базой.
Не запускайте два процесса с одним Telegram-токеном.

## Слои

| Слой | Где работает |
|---|---|
| Управление | Telegram-бот и HTTP API Mini App в сервисе `bot` |
| Агент | Классификатор намерения, ответы по справке, агент с поиском по активному профилю |
| Обработка материалов | Сервис `worker`, очередь и статусы в PostgreSQL |
| Хранение | PostgreSQL + pgvector, закрытое S3 для оригиналов и Markdown |
| Доставка | Сервисы согласования и расписания, адаптеры в `app/publishers` |

Для демо реализация доставки — Telegram. VK и MAX остаются точками расширения.
Instagram не указан в предоставленном описании хакатона.

## Метрики соцсетей

У слоя интеграций два интерфейса. `Publisher` отправляет согласованные посты,
`AnalyticsSource` читает счётчики по ID канала и постов. Сервисы выбирают адаптеры
по платформе. Публикация и аналитика Telegram зарегистрированы в `app/container.py`.
Задача второго слоя `collect_social_metrics` запускается при старте и каждый час.
Она проходит по профилям, запрашивает текущие счётчики и записывает снимки в PostgreSQL.
Отчёт и графики читают эти снимки из базы. Для сбора метрик модель не вызывается.

- Подписчики активного канала запрашиваются через Bot API.
- Просмотры и пересылки читаются через MTProto (`channels.getMessages`). Для этого
  добавьте `TELEGRAM_API_ID` и `TELEGRAM_API_HASH` из [my.telegram.org](https://my.telegram.org/apps)
  в `.env` и пересоздайте контейнер бота. Используется его существующий `BOT_TOKEN`.
  Контейнеру нужен прямой исходящий доступ к MTProto. `TELEGRAM_PROXY` применяется к Bot API.
- Отчёт выбирает посты, опубликованные за указанный период. У них показываются
  накопленные счётчики на последнем успешном замере. На главной в «Аналитике» есть
  графики за 24 часа, 7 и 30 дней и календарь с границами по первому замеру и текущей дате.
  Сбой оставляет пропуск в истории. Dry-run публикации исключены из запросов к соцсети.
  Если Telegram подтверждает удаление сообщения, последующие опросы этого поста прекращаются,
  а предыдущие снимки остаются в базе.

## Пул постов

С главной открывается пул всех постов активного профиля. У каждой версии свой снимок текста
и изображения, ссылка на предыдущую версию и источник изменения. Запросы из чата связаны
с записью сообщения. Пост из плана связан с его пунктом и, если план создан в чате, с запросом
на план. Для фото пользователя хранится ссылка на фотобанк, для генерации — модель и полный
промпт, переданный генератору. Замена или удаление фото записывает новую версию.

Согласование, отклонение и публикация привязаны к конкретной версии через журнал событий.
Для постов, созданных до добавления истории, доступны существующие текстовые версии.
Детали происхождения и предыдущие фото начинают сохраняться с момента обновления.

## Профили и материалы

В профиле хранятся бизнес-факты, голос бренда, визуальные правила, ограничения и канал.
Для подключения канала Telegram проверяет права администратора у пользователя
и право публикации у бота.
PDF отправляется тяжёлой модели порциями страниц с визуальным входом. Изображения
обрабатываются как визуальные референсы. Можно загрузить PDF и изображения,
включая JPEG, PNG, WebP, GIF, TIFF, HEIC, AVIF и SVG. Презентации экспортируйте в PDF.
На профиль отведено 100 МБ оригиналов. Для обработки PDF действует предел 180 страниц,
на одну часть — 35 МБ исходного PDF.
В «Материалах» можно добавить публичный сайт. До четырёх HTML-страниц сохраняются
одним Markdown-документом и поступают в ту же очередь обработки.

Воркер сохраняет отдельные Markdown-фрагменты и эмбеддинги с привязкой к исходнику.
Повторная загрузка тех же байтов в тот же профиль определяется по SHA-256. Удаление
сразу убирает материал из поиска. Воркер затем удаляет связанные объекты и индекс.
Изменение полей профиля сохраняет существующие Markdown и индекс. Для новых файлов
воркер подставляет актуальные поля профиля. Лёгкая модель получает только выбранные
Markdown-фрагменты и информацию активной компании. Ошибки обработки видны в интерфейсе,
где можно повторить конкретное задание.

## Согласование

Чат направляет запросы по справке и маркетинговые задачи по разным сценариям.
Явная просьба о публикации формирует действие с кнопкой подтверждения. Если пост изменился,
Mini App просит открыть новую версию и подтвердить действие снова. Расписание, отмена
и публикация используют те же сервисы, что Telegram-бот. Автономные черновики можно включить через
`ENABLE_AUTO_DRAFTS=true`. Для тестов сохраните `PUBLISH_DRY_RUN=true`.

## Контент-план

В чате можно попросить план на неделю (пять тем) или на 30 дней (двенадцать тем).
Модель подбирает темы по профилю, найденным материалам и недавним постам. Даты
начинаются с завтрашнего дня, время по умолчанию — 10:00 в часовом поясе сервера.
План появится в разделе «Контент-планы» на главной. Владелец компании может
отредактировать темы до утверждения, утвердить или архивировать план.

Планировщик каждые пять минут проверяет утверждённые планы. Черновик становится
доступен на согласование примерно за сутки до даты. Дата из плана подставляется
в форму расписания, где её можно поменять. Для публикации нужно отдельно
подтвердить пост. Архивирование останавливает создание новых черновиков по
этому плану. Уже созданные посты остаются доступны на главной.

Документация: [Telegram Mini Apps](https://core.telegram.org/bots/webapps),
[OpenAI file inputs](https://developers.openai.com/api/docs/guides/file-inputs),
[pgvector](https://github.com/pgvector/pgvector).

## Сценарии AI

Бот и Mini App вызывают один Python-харнес. Лёгкая модель классифицирует запрос в
JSON. Для действий она извлекает параметры по схеме, а код вызывает нужный сервис.
Запрос о проекте ищет разделы в справке платформы. Вопрос о канале или площадке
ищет в отдельном каталоге интеграций. Оба каталога — Markdown с поиском по словам.
Вопросы о компании и генерация контента используют материалы только активного
профиля из PostgreSQL и pgvector.

У текста поста и задания для генератора изображений отдельные промпты. Просьба
запланировать или опубликовать пост возвращает предложение действия. Mini App
отправляет его в API после подтверждения пользователя и проверки версии поста.


## Управление и проверка AI

В личном чате оставлена команда `/start` и свободный текст. Если профиль не выбран
и подходящих компаний несколько, бот просит выбрать компанию. Запросы на
публикацию или расписание показываются на главной в Mini App, где их можно
подтвердить. В разделе профиля доступны комментарии, настройки автоответов,
расходы, месячный лимит, журнал, диагностика канала и фотобанк. Из фотобанка можно
создать черновик, а в карточке поста заменить изображение. На главной доступны
история опубликованных и отклонённых постов и отчёт за 7, 30 или 90 дней.
Экран отчёта строит график и сводку по данным из базы без вызова модели.

Поиск материалов выбирает до шести ближайших фрагментов активного профиля по
косинусному расстоянию, отбрасывает совпадения с расстоянием выше 0,65 и передаёт
до 8000 символов. Эмбеддинг повторного запроса сохраняется в памяти на 10 минут.
Результаты поиска запрашиваются в базе каждый раз, поэтому удалённые файлы
исчезают из контекста сразу.

В запросах к Luna постоянные инструкции идут перед историей и вопросом. Короткие
запросы оставляем короткими. Наличие попадания в кэш измеряется по
`usage.prompt_tokens_details.cached_tokens`, а не по времени ответа.
Для изолированного прогона используйте `pytest tests/test_harness.py tests/test_agent.py`.
Живой ключ для этих тестов не требуется.

### Внешние зависимости

- Telegram Bot API нужен для входа, регистрации кнопки меню, получения событий и публикации.
  Боту нужны права на публикацию в канале. Для комментариев подключите группу обсуждения.
- Публичный HTTPS-адрес должен вести на Mini App. Для демо можно использовать туннель.
  После смены его адреса обновите `MINIAPP_PUBLIC_URL` и перезапустите бота. Для меню
  используется этот адрес, а отдельная прямая ссылка BotFather имеет собственную настройку.
- OpenAI API использует Luna для чата и обработки материалов, модель эмбеддингов для
  индекса и поиска, а при `IMAGE_PROVIDER=openai` — модель изображений для иллюстраций.
- В Docker Compose локальный PostgreSQL хранит состояния и pgvector-индекс, а RustFS
  хранит оригиналы и Markdown. Для переноса стека нужны оба тома и том бота с изображениями.

## Разбор поста и веб-поиск

«Разобрать пост» в аналитике и запрос «Разбери пост №42» в чате читают одну запись
по ID публикации. При первом запросе GPT-6 Luna получает текст, название и описание
компании, до 14 точек динамики и доступные замеры сопоставимых постов. Повторный запрос возвращает сохранённый разбор.

Запросы к актуальным внешним фактам идут через GPT-6 Luna и инструмент `web_search`
Responses API. В основной контекст передаётся короткая справка с максимум тремя
ссылками. Каждый запрос на актуальные факты запускает свежий поиск, включая повтор
того же вопроса. Редактор и генератор запрашивают справку только для задач, где нужны
внешние факты. Поиск использует до двух вызовов инструмента за запрос.

Редактор предложений сохраняет текст и порядок вложений как новую версию.
Для Telegram доступны фото и MP4, до десяти вложений на пост. Изменения возвращают
пост на согласование.

### Черновики в чате

Стиль можно назвать в запросе: «обычный», «официальный», «соцсети», «Анти-ЛЛМ»
или «научный». Если ракурс или исходная фотография неясны, ассистент задаёт
один вопрос. Когда визуальный замысел очевиден, он может сам добавить
иллюстрацию. Явное «без фото» отключает генерацию картинки.

Перед научным постом и при запросе внешних фактов о новостях, законах и
исследованиях ассистент ищет подтверждения. Если центральный факт проверить
не удалось, он просит источник или уточнение. Правила «Анти-ЛЛМ» адаптированы
из [blader/humanizer](https://github.com/blader/humanizer).
