# Какую нейросеть подключать: варианты, цены, ограничения

Разбор для выбора LLM и генератора картинок. Цены взяты с официальных страниц 13.11.2026:
[Yandex AI Studio](https://aistudio.yandex.ru/docs/ru/ai-studio/pricing),
GigaChat для [физлиц](https://developers.sber.ru/docs/ru/gigachat/tariffs/individual-tariffs) и
[юрлиц](https://developers.sber.ru/docs/ru/gigachat/tariffs/legal-tariffs),
[OpenAI](https://developers.openai.com/api/docs/pricing),
[DeepSeek](https://api-docs.deepseek.com/quick_start/pricing).
Курс для пересчёта — условные 100 ₽ за $, без наценок посредников.

## Главные ограничения, от которых зависит выбор

1. **Сервер в России.** С нашего VPS (Москва) не открывается `api.telegram.org`, нужен прокси
   (`TELEGRAM_PROXY`). Российские сервисы (Yandex, GigaChat) доступны напрямую. OpenAI из РФ
   напрямую не работает и не принимает российские карты: только через посредника (ProxyAPI и
   аналоги, оплата в рублях, наценка — единицы процентов) или через прокси.
2. **Агенту нужен вызов инструментов** (function calling). Наш агент общается с моделью в формате
   OpenAI. Модель без нормального вызова инструментов не сможет «создать черновик», «показать
   посты», «сделать отчёт».
3. **Русский язык и тон бренда.** Посты пишутся по-русски — модель должна писать живо, без
   канцелярита.
4. **Данные клиентов.** В комментариях есть имена подписчиков. Российский провайдер проще с точки
   зрения 152-ФЗ, зарубежный через посредника — серая зона для коммерческого запуска.

## Локальная нейросеть: стоит ли

Токены действительно не стоят денег, но нужен компьютер, который **работает 24/7**. Тогда
компьютер — это сервер.

- **Наш VPS (2 ГБ ОЗУ) не подходит.** Влезают только модели 1–3 млрд параметров, а они плохо пишут
  по-русски и почти не умеют вызывать инструменты.
- **Нормальное качество для русского — от 14 млрд параметров** (Qwen3 14B, T-Pro на базе Qwen3):
  нужно 16+ ГБ памяти. На процессоре модель 7B выдаёт ~5–15 токенов в секунду. Пост в 300 слов —
  около минуты, ответ агента с инструментами — несколько минут.
- **Сервер с видеокартой** решает скорость, но стоит в разы больше всех облачных вариантов при
  нашей нагрузке: облако обходится в 70–900 ₽ на компанию в месяц.
- **Когда локальная модель оправдана:** очень много компаний (сотни), запрет на передачу данных
  наружу, или уже есть своё железо.
- **Подключение без нового кода.** Ollama отдаёт OpenAI-совместимый API, поэтому достаточно
  `LLM_PROVIDER=openai`, `LLM_BASE_URL=http://localhost:11434/v1`, `LLM_MODEL=qwen3:14b`.

**Вывод:** для хакатона и первых клиентов — облако. Локальная модель — вариант на будущее для
закрытых контуров.

## ChatGPT: что реально можно сделать (критерий 12 ТЗ)

ТЗ просит проверить, можно ли использовать **существующий аккаунт ChatGPT**, и не подменять его
незаметно отдельным API-ботом.

| Способ | Работает? | Что даёт | Ограничения |
|---|---|---|---|
| **Подписка Plus/Pro как API** | ❌ | — | Подписка и API оплачиваются отдельно. Официального способа вызывать модели «за счёт подписки» из своего кода нет |
| **Свой GPT с Actions** (OpenAPI) | ✅ | Владелец в ChatGPT пишет «сделай пост про акцию», GPT вызывает наш API → черновик приходит в Telegram на согласование | Нужен публичный HTTPS-адрес нашего сервера. Интерфейс — ChatGPT, а согласование остаётся в Telegram |
| **Приложение / MCP-коннектор** (Developer mode) | ✅ частично | Тот же сценарий через MCP-сервер | Документация OpenAI противоречит сама себе: на Plus/Pro запись может быть недоступна (только чтение), полная поддержка — на Business/Enterprise/Edu. Проверять на своём аккаунте |
| **Codex CLI со входом через ChatGPT** (`codex exec`) | ⚠️ технически да | Модель вызывается из скрипта в счёт лимитов подписки | Это агент для кода, а не чат-API. Тариф рассчитан на личное интерактивное использование — круглосуточная автоматизация на сервере — серая зона. Из РФ нужен прокси. Только как эксперимент на демо |
| **Автоматизация браузера с chatgpt.com** | ❌ | — | Нарушает правила OpenAI, ломается от капчи и обновлений интерфейса. Не делаем |

**Что показать на защите:**
1. Честно: подписка не равна API, OpenAI из РФ недоступен напрямую.
2. Работающий вариант — **свой GPT с Actions** (или MCP-приложение) поверх нашего API:
   авторизация в аккаунте ChatGPT, создание черновика из ChatGPT, черновик приходит в Telegram,
   без согласования ничего не публикуется.
3. Основной «мозг» бота — облачная LLM через API: это требование 24/7, которое подписка не даёт.

**Что сделать в коде:**
- Yandex AI Studio даёт OpenAI-совместимый API. Скорее всего, хватит текущего
  `openai_provider.py` с `LLM_BASE_URL` Яндекса; вызов инструментов нужно проверить на живой модели.
- GigaChat — свой формат функций: отдельный провайдер (задача A9) или OpenAI-совместимая прослойка.
- Разным задачам — разные модели: черновики и отчёты — сильная модель, ответы на комментарии и
  классификация — дешёвая. Учёт расходов (`/costs`) уже есть, маршрутизация по задачам — доработка.
- Цены в `.env` (`LLM_PRICE_INPUT_PER_1M` и др.) поставить под выбранную модель, чтобы `/costs`
  считал верно.
