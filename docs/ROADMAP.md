# Доработки для коммерческого использования

Документ для сдачи (п. 8.6 ТЗ): что нужно сделать, чтобы один оператор обслуживал десятки
компаний за деньги.

## 1. Площадки и контент

| Доработка | Зачем | Объём |
|---|---|---|
| Публикаторы **ВКонтакте** (`wall.post`, фото, статистика `stats.getPostReach`) и **MAX** | целевые площадки из ТЗ | 2–4 дня каждая |
| Адаптация текста под площадку (длина, структура, хештеги) | п. 3.3 ТЗ | 1 день |
| Контент-план на неделю/месяц с согласованием целиком | регулярная работа без ручных задач | 2 дня |
| Автономные черновики по плану и сам выбор тем | п. 3.3 «самостоятельное предложение тем» | 1–2 дня |
| Сценарии коротких видео (раскадровка, текст, хештеги) | п. 3.3 | 1 день |
| Анализ конкурентов (сайт, публичный канал) и стратегия | п. 3.2 | 2–3 дня |
| AI-проверка перед согласованием: орфография, запреты бренда, выдуманные цифры | п. 3.3 «проверка материалов» | 1 день |
| Несколько вариантов текста на выбор, голосовые задачи | удобство | 1–2 дня |

## 2. Аналитика

| Доработка | Зачем | Объём |
|---|---|---|
| Просмотры и охваты Telegram через MTProto (служебный аккаунт) | Bot API их не отдаёт | 2–3 дня |
| Статистика VK, лучшее время публикации по истории | рекомендации на данных | 2 дня |
| Связь с заявками и продажами (UTM, промокоды, CRM-вебхук) | п. 3.6 «влияние на продажи» | 3–5 дней |

## 3. Платформа

| Доработка | Зачем | Объём |
|---|---|---|
| PostgreSQL вместо SQLite, миграции Alembic | много компаний, обновления без потери данных | 2 дня |
| Redis для FSM и очереди задач | состояния переживают перезапуск, масштабирование | 1–2 дня |
| Вебхуки вместо long polling, health-check, мониторинг и алерты | надёжность 24/7 | 1–2 дня |
| Резервное копирование БД по расписанию | сохранность данных клиентов | 0,5 дня |
| Маршрутизация моделей по задачам (дешёвая — для комментариев, сильная — для постов) | ниже расходы | 1 день |
| Веб-кабинет администратора (компании, расходы, журнал) | удобнее, чем команды в боте | 3–5 дней |

## 4. Безопасность и право

| Доработка | Зачем |
|---|---|
| Шифрование токенов площадок в БД (сейчас секреты только в `.env`) | п. 5 «защищённое хранение учётных данных» |
| Роли внутри компании (несколько сотрудников, разные права на согласование) | п. 4 «индивидуальные правила согласования» |
| Политика обработки персональных данных, согласие клиентов, хранение в РФ (152-ФЗ) | коммерческий запуск |
| Договор с провайдером LLM на юрлицо, закрывающие документы | бухгалтерия |

## 5. Деньги

| Доработка | Зачем |
|---|---|
| Тарифы для клиентов и оплата (ЮKassa) | монетизация |
| Лимиты по тарифу на посты, картинки и AI-расходы (основа уже есть: `/costs`, `/budget`) | контроль маржи |

**Себестоимость** одного AI-маркетолога — около 200 ₽ в месяц плюс доля сервера
([COSTS.md](COSTS.md)). Это оставляет большой запас для подписки клиента.
